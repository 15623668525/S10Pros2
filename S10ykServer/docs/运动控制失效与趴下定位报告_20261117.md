## 3. 视频故障定位

- RTSP 服务器（8554）**活着**：TCP 可达、协议应答正常；
- 但 `DESCRIBE rtsp://…/video0|video4 → 404 Not Found`：**流没有注册**——相机推流节点死了，不是网络问题；
- 相机进程在 205 用户容器 `ps` 中不可见（持有者在厂商容器/宿主 PID 命名空间，同 D-010/D-034 模式）；
- 崩溃时间与运动栈崩溃（19:22:04）一致 → **相机节点随厂商栈一起崩，重启后没有起来**。

## 5. 根因判断与建议

**根因（19:40 确认）**：用户手柄 APP 显示机器人处于**休眠模式**。休眠模式行为与本报告全部症状吻合：

| 症状 | 休眠模式解释 |
|---|---|
| 突然趴下 | 休眠即趴下+关节下电 |
| CSV 关节列全 0（18:43–19:04 共 21 分钟） | 关节下电后温度遥测读不到——不是"通信故障"，是**下电** |
| 19:04:31 关节"恢复" | 期间可能短暂唤醒过（或部分上电），后又休眠 |
| 运动指令无效（state 恒 0） | 休眠中运动控制器忽略指令 |
| RTSP 404（流未注册） | 休眠关闭相机推流节能 |
| 音频正常 | sayd 是我们自部署服务，不受休眠影响 |
| 19:22:04 会话终止 / 19:22:50 新会话 | 进入/退出休眠时厂商栈重启日志会话（非崩溃） |
| 19:27:44 站立成功后又塌回 | 短暂唤醒后再次休眠（或唤醒不完整） |

**待查**：为何在"运控控制过程中"触发休眠——是**闲置自动休眠**（控制台断续操作间 idle 超时？）、还是手柄 APP 上误触了休眠开关。需留意复现条件；若确认是自动休眠，需查厂商休眠超时配置（ASDU/robotserve 配置项），并对控制台加"保活/防休眠"或休眠状态提示（前端可从 state=0+gait=0+高度骤降识别并提示"机器人可能休眠，请用手柄唤醒"）。

**恢复步骤**：
1. 手柄 APP 上**退出休眠/唤醒**机器人；
2. 回控制台：站立（高度应 ≥0.33）→ 摄像头画面恢复 → 低速行走验证；
3. 我这边可远程复验（遥测 state/height、RTSP DESCRIBE）。
