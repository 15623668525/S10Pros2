# 真人录音样本无效性诊断（2026-11-26 14:40–14:50）

## 结论：14:30 采集的录音里没有真人语音，此前 A/B 结论作废

用户要求"换算法方向做谱减法"。用 14:30 录的 `human_voice_ab.raw`（56.8 s）做谱减实验时，发现所有算法（谱减/Wiener/MMSE/陷波）都"削语音"。深挖后发现**根因不是算法，而是录音样本本身没有语音**。

## 证据链

### 1. 噪声与语音帧频谱几乎完全相同
把 100 ms 帧按能量分最高 20%（"语音"）和最低 20%（"噪声"），逐频段比能量：

| 频段 | 噪声帧 | "语音"帧 | 比值 |
|---|---:|---:|---:|
| 0–100 Hz | 254727 | 243912 | 0.96 |
| 200–300 Hz | 1028575 | 1068998 | 1.04 |
| 500–800 Hz | 75259 | 74798 | 0.99 |
| 2000–3000 Hz | 49327 | 49163 | 1.00 |
| 6000–8000 Hz | 35560 | 35124 | 0.99 |

若有真人语音，语音帧在中频带应显著高于噪声帧。实际全程 ≈1.00，说明两类帧是同一个稳态声源。

### 2. 全程被 224 Hz + 244 Hz 电机基频主导
频谱 TOP 峰值：224.1 Hz（幅度 3.3 亿）、244.1 Hz（1.3 亿），是其他频率的几十倍。每 5 秒测主频，全程都是 224/244 Hz。224 Hz 邻带能量是语音带（500–3 kHz）的 **15–29 倍**。

### 3. 语音带无动态起伏（决定性证据）
对 500–3000 Hz 带通后的信号算能量包络：

- RMS 范围：1000–1278（全程 56 秒）
- 动态范围 p90/p10 = **1.14 倍**
- 真人说话该比值应 **>3 倍**（数数字时语句间有停顿，静音与发音差几十倍）

全程语音带能量恒定，无语句起伏 → **没有真人语音进入麦克风**。

### 4. 通道间相关性低但不影响判断
ch0-ch1 corr=-0.45、ch1-ch2 corr=0.04，三路不是简单副本，但都记录了同一个电机噪声场。

## 为何会录到空样本（推测）

- 录音用 `arecord -d 90` 后台启动，用户说话时刻与录音窗口可能错位
- 用户距麦克风 1–2 m，而电机噪声在麦克风附近（车身），SNR 极低，人声被淹没
- 也可能说话期间对讲/播报占用了采集链路（需复查）

## 下一步：重新采集有效样本

重新录音时必须**实时验证语音带动态范围 >3 倍**才算有效，流程：
1. 用户先说一句话，同时采集 3ch
2. 立即带通 500–3 kHz 算 p90/p10
3. 若 >3 → 样本有效，继续做 A/B；若 <2 → 重录（调整距离/音量/增益）
4. 有效样本上重新跑 speex / 谱减 / 陷波对比

## 补充：第二次录音（14:45，贴近麦克风重录）与三算法验证

### 第二次录音有效性
用户贴近麦克风（30–50 cm）重录 30 s（`human_voice_v2.raw`）。这次**录到了语音**，但极弱：

- 逐秒语音带（500–3 kHz）RMS：基线 ~1150，说话峰值秒 t=11s=1924、t=12s=1593、t=16s=1821
- 整体语音段/噪声带比仅 **1.27（+2.1 dB）**——说话时+SNR 很低
- 电机 224 Hz 邻带仍是语音带的数千倍
- 按 p90/p10 全局判据仍 1.18 < 3（因大部分秒无语音），但**局部语音段真实存在**

### 三算法在有效语音段（t=10–18 s）上的验证结果

| 算法 | 结果 | 判定 |
|---|---|---|
| **陷波 224/244 Hz** | 语音带（500–3 kHz）保留 **100%**（陷波不碰该频段），电机基频被压 | ✅ 安全，但只解决带外基频，带内谐波仍在 |
| **谱减（纯噪声段估谱）** | 语音带 RMS "放大" **181%~296%** | ❌ 音乐噪声（musical noise）虚高，非真实语音增强 |
| **Wiener / MMSE-STSA** | 语音保留 50%/10%，包络相关 0.22/0.12 | ❌ 严重削语音 |

### 噪声结构
电机噪声是**离散谐波线**：227、469、945/977、2359 Hz（224/244 Hz 的整数倍）。人声共振峰在 650–980 Hz、1300–1500 Hz，落在谐波间隙——理论上陷波谐波可保留语音，但实测带内谐波能量低，陷波收益有限。

### 最终技术判断（诚实结论）

1. **这段环境的根本约束是采集 SNR 太低**：即使贴麦说话，语音也只比底噪高 2 dB。降噪算法在这么低的输入 SNR 下无法凭空恢复语音。
2. **软件降噪三条路线均失败**：speex 削语音、谱减出音乐噪声、Wiener/MMSE 更差。继续调参数无意义。
3. **真正该做的是硬件/链路层改善**，按收益排序：
   - 增大 Mic 硬件增益或加前置放大（当前已 50 dB 满格，需查 ADC 前端）
   - 确认采集通道是否选对（ch1 最强已用；但 224 Hz 在 ch0/ch1 都强，可能机身结构传导）
   - 物理隔离电机噪声传播（麦克风远离电机/加减震）
   - 若机器狗静止时说话，SNR 会显著改善——可验证噪声是否随运动变化
4. **可保留的唯一无损处理**：224/244 Hz 陷波（语音带零损），但收益有限（只去基频，不去带内谐波）。
5. **不建议上线任何软件降噪**，L3 维持默认关闭；L1+L2 选路继续有效。
