## P0 离线包制作（现场窗口前，本机+204，约 1h，无风险）

**前置**：204 可达（直连 625 失败时走 frp 隧道 <FRP_IP>:7300）；本机可上 PyPI。

| 步骤 | 命令要点 | 产物 |
|---|---|---|
| P0.1 wheels | `pip download --platform manylinux2014_aarch64 --python-version 3.12 --only-binary=:all: -d pkg/wheels onnxruntime opencv-python-headless numpy` | aarch64 wheels ~60-80MB |
| P0.2 模型+资产 | 从 204 打包 `/opt/s10yk/models/`（26MB）、`/opt/s10yk/assets/`（~1MB）、数据目录样例 | pkg/models, pkg/assets |
| P0.3 代码 | 仓库 `S10ykApp/{backend,frontend}` 当前版打包 | pkg/backend, pkg/frontend |
| P0.4 证书 | `openssl req -x509 -newkey ec -nodes ...`，**SAN = IP:10.21.33.103, IP:<ROBOT_IP>, DNS:localhost** | pkg/certs/{server.crt,server.key} |
| P0.5 drdds 提取 | 经 204→205→sshpass→106：`dpkg -L drddslib drdds-ros2-msgs` 定位文件列表 → tar 打包（含 lib/*.so + python3.12/site-packages/drdds + 运行时） | pkg/drdds_aarch64.tar.gz ~10-20MB |
| P0.6 传输 | 整包 pscp 到 205（经 204 跳板或直连 9822，~100MB 预留 20-40min） | 205:/home/user/pkg/ |

**验收**：205 上 `ls pkg/` 六项齐全；`pip install --no-index --dry-run` 通过。

## P1 冒烟验证（30min，无风险，可随时中止）

**前置**：P0 完成；现场无人使用 204 控制台做运动操作（只读探测不影响）。

1. **DDS 类型兼容（不碰真实话题）**：205 上 source jazzy，用迁移来的 Steer 类型在**测试话题 `/s10yk_smoke`** 上自发自收一帧——验证类型注册与序列化兼容，**不向 /STEER 发布任何内容**（避免干扰 204 正在控制的狗）。
2. **真实遥测订阅**：订阅 /MOTION_INFO 收 ≥10 包（仅订阅，无发布）；确认与 106 的 DDS 发现互通。
3. **音频链路**：arecord 3s 采一段 + aplay 回放本机确认；sayd 18081 现有服务不触碰。
4. **RTSP**：已验证过，仅复验一次 127.0.0.1:8554 拉流。

**验收**：冒烟全绿 → 进 P2。**任一失败**：启用备选（DDS 类型不兼容 → GenericPublisher 方案 B，工时 +2h）；无回滚需要。

## P2 板上落盘（1.5h，无风险——只装不动）

1. 目录树：`/opt/s10yk/{backend,frontend,models,certs,assets,data,venv}`（sudo）。
2. venv：`python3 -m venv /opt/s10yk/venv && venv/bin/pip install --no-index --find-links /home/user/pkg/wheels ...`。
3. drdds 落位：tar 解到 `/opt/ros/jazzy` 对应路径（**不 dpkg 注册**，纯文件叠加，不干扰厂商包管理；解压前记录 jazzy 目录基线便于卸载）。
4. 模型/资产/证书/代码归位；权限 640/750。
5. **端口前置检查**：`ss -tln | grep -E ':(18090|18443) '` 必须为空，非空中止。

**验收**：venv 内 `import cv2, onnxruntime, numpy` 成功；模型文件 md5 与 204 源一致；端口检查通过。
**回滚点**：整目录 `rm -rf /opt/s10yk` + 按 jazzy 基线删除 drdds 叠加文件即净。

## P3 本机化改造 + 服务单元（1.5h，无风险——服务先不启动）

1. **代码改造（决策点 D1 默认 B）**：`_ssh103()` 加 local 分支（SAY_HOST 未设或 = "local" 时 subprocess 直跑命令）；mic_front 拉起与 talk arecord 管道同步本机化。改造在本地仓库完成 → 脱敏 → 上传，本地全套单测先过。
2. **systemd 单元**：
   - `s10yk-backend.service`：`ExecStart=/opt/s10yk/venv/bin/python app.py`，`Environment=S10YK_TOKEN=<现场生成强令牌>`，`Environment=S10YK_SAY_HOST=local`，Restart=always，enable。
   - `s10yk-persond.service`：线程/帧率起步值 `PERSON_THREADS=4`、`PERSON_FPS=2`（决策点 D2 阶梯第一档）。
   - 单元文件加注释性 Conflicts 声明（防与未来容器化重复部署）。
3. sayd（s10yk-say）**不动**，后端经 127.0.0.1:18081 直连。
4. 单元文件 `systemd-analyze verify` 语法校验。

**验收**：`systemd-analyze verify` 0 error；本机回归测试通过。
**回滚点**：删除两个单元文件即可，204 侧零影响。

## P4 只读并行验证（1h，204 继续运行，边界 = 决策点 D3）

1. 205 `systemctl start s10yk-backend`（persond 单独手动跑 60s 测 ARM 推理帧率，不 start 常驻）。
2. 验证清单（全部只读）：
   - 页面打开：`https://10.21.33.103:18443`（自签证书放行）+ 登录 token 生效；
   - 状态轮询、电量/姿态遥测实时刷新；
   - 视频流拉通（延迟与画质主观记录）；
   - `top` 观察 backend CPU <10%、内存 <300MB；205 整机 load 不明显抬升；
   - persond 实测：60s 推理统计（单帧耗时、丢帧率）→ 按 D2 阶梯定档。
3. **边界纪律**：不点摇杆、不喊话、不对讲（写操作仍走 204）。

**验收**：清单全过 + D2 定档结论。**失败处置**：性能问题回 P3 调参；认证/页面问题修代码重传；DDS 异常回 P1 复测。
**回滚点**：205 `systemctl stop s10yk-backend`，一切归零。

## P5 切换（30min，有影响窗口，需用户在场确认）

**前置**：P4 全绿；**用户明确说"切"**；切换窗口选业务空闲时段。

1. 204：`systemctl stop s10yk-backend s10yk-persond && systemctl disable s10yk-backend s10yk-persond`（**disable 只这两个，其余服务一律不动**；数据/文档/备份全部保留）。
2. 205：`systemctl enable --now s10yk-backend s10yk-persond`。
3. **全功能验收**（此时运动指令唯一来源 = 205）：
   - 摇杆运动（前进/转向/急停）；
   - 一键喊话 + 双向对讲（重点回归 v3.5.x 的全部修复点）；
   - 人员检测预警播报（真人走动触发）；
   - 音量调节、亮度等杂项。
4. zenoh-bridge-dds（205 上连 204:7447）：`stop + disable`。
5. 重启自启验证：`reboot` 一次，确认 205 两服务自动拉起、页面可用（R7 闭环）。

**回滚**：205 `systemctl disable --now s10yk-backend s10yk-persond` → 204 `systemctl enable --now s10yk-backend s10yk-persond`，**10 分钟内恢复原架构**。

## 中止准则（任一触发即停止推进、回到上一回滚点）

- P1 类型兼容失败且 GenericPublisher 备选未获用户同意；
- P2 磁盘/权限受阻（不强行清理厂商目录）；
- P4 只读验证出现 DDS 风暴、load 飙升 >8 或厂商服务异常；
- P5 验收中任一安全项（急停、运动响应）不合格——**急停优先级最高**。
