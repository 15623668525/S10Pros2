# 前进与转向同时使用调研报告

日期：2026-11-17 ｜ 结论：**机器人本体支持，我们的控制台 UI 目前不支持（可低成本补上）**

## 1. 问题

机器狗的前进（`/STEER.data.x`）和转向（`/STEER.data.yaw`）能否同时使用（边走边转/走弧线）？

## 2. 结论与证据链

### ✅ 机器人侧：支持，两通道独立

| 证据 | 来源 |
|---|---|
| `/STEER`（`drdds/msg/Steer`）**单帧同时携带 `data.x` 与 `data.yaw`**，两个自由度在同一消息里、无互斥字段 | `ros2 interface show`（见《遥控器控制通路实测_20261116》§2） |
| `data.x` 单独有效：`vel_x ≈ 0.115 + 1.19·x`（线性，R²高） | 同上 §8.2 注入实测 |
| `data.yaw` 单独有效：`vel_yaw ≈ 1.22·yaw`（左）/ `1.32·yaw`（右） | 同上 §8.3 注入实测 + 《速度范围实测报告_20261117》全量程标定 |
| 厂商 `/NAV_CMD`（`x_vel` + `y_vel` + `yaw_vel`）官方定位就是"**导航规划的速度指令**"——导航路径天然是曲线（前进+转向同时），厂商文档明示线速度与角速度同帧下发 | 《S10软件开发指南0915》p60-61 |
| 遥控器本身就是组合输入（前后杆+转向轴），正常驾驶即边走边转；轮足形态下这是基本操作 | 产品使用观察 |
| 我们后端 `publish_steer(x, yaw)` 就是把两个值放进**同一帧** 20Hz 下发，代码零互斥 | `backend/app.py` `nav_loop()` |

### ❌ 控制台侧：UI 互斥，无法同时发

- 前端十字盘 `DPAD_DIR` 是**单值状态**：`fwd/back/left/right` 互斥，多指按下时**后按的方向覆盖先按的**（按住 ↑ 再按 →，机器人从前进切为纯原地转向）；
- 键盘同样：任一方向键 `keyup` 即整体置零（`window.addEventListener("keyup", … dpadSet("stop"))`）；
- 结论：**这是 UI 设计限制，不是机器人限制**。后端 `/api/nav` 协议本来就是 `{x, y, yaw}` 三值同发，后端与机器人链路**零改动**即可支持组合。

### ⚠️ 组合工况从未实测

- 复查 2026-11-16 遥测日志（`evidence/rc_listen_20261116.log`，2404 帧 MOTION_INFO）：**vx 与 wz 同时 >0.05 的帧数为 0**——当时实验只推了前后，x+yaw 同时注入从未做过；
- 已知会影响组合体验的实测特性（来自单通道标定）：
  1. 转向**左右不对称**（±0.12 输入下 +0.098 / −0.154 rad/s）→ 弧线左右半径不同；
  2. 转向**归零残余阻尼**（0.8s 内仍有 ~−0.055 rad/s）→ 回直后轻微画弧；
  3. 前进有 **~0.15 m/s 最小步速地板** + 1.5~2s 刹停惯性；
  4. 按低速档估算（x=0.16→≈0.35 m/s，yaw=0.15→≈0.19 rad/s）：**转弯半径 ≈ 1.8 m**，最高档组合半径 ≈ 1.2 m——想转小半径需加大 yaw 档。

## 3. 若要启用组合控制（建议方案）

1. **UI**（唯一需要改的地方）：十字盘从"单方向"改为"**方向 + 转向可叠加**"——例如 `DPAD_DIR` 改成 `{fwd/back}` 与 `{left/right}` 两个独立状态位，按住 ↑ 同时按 → 即 x+yaw 同发；键盘支持组合键（↑+→，且任一键松开只清该轴）。改动集中在 `dpadSet()/dpadBind()`，约 30 行。
2. **后端**：零改动（`/api/nav` 与 `nav_loop` 已按帧组合下发）。
3. **上机前安全实测**（建议项）：
   - ARM 后低速档发 `x=0.16, yaw=0.15` 持续 2s，看 MOTION_INFO 的 vx/wz 是否同时响应、是否仍符合单通道标定比例（验证有无耦合/限幅）；
   - 左右两个方向各测一次（已知不对称）；
   - 敏捷步态（平地 0x3002）下重复一次（文档称其速度响应更好，导航模式用的就是它）。
4. 遗留风险（低）：组合时 `/STEER` 与遥控器并发的优先级问题仍未验证（历史遗留项，与组合本身无关）。
