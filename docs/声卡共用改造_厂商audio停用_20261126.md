# 声卡共用改造：厂商 audio 停用 + sayd 走共享设备（2026-11-26）

## 目标

让"别的应用"能和我们的喊话/对讲**共用同一块物理声卡**，而不必各自独占。前置条件是确定厂商 audio 节点不再抢占声卡。

## 关键认知（避免混淆）

**"厂商 audio 不再使用" ≠ "别的应用能共用"**，且共用**不靠话题化**：

| 层 | 作用 | 本次动作 |
|---|---|---|
| 应用 | sayd / 别的应用 / 厂商 audio | 厂商 audio 停用 |
| 访问 | `plughw`（独占）vs `default`→pipewire（混音） | sayd 改 `default` |
| 硬件 | card0 playback ×1（ES8323） | 不变 |

话题化只解决"数据分发"（多人订阅同一份音频流），不解决"多个应用同时写声卡"——后者是 ALSA 访问层的事。

## 变更一：停用厂商 audio_node.service（106 / NOS）

### 现状（改前）
- 机型 CD1（`/var/opt/robot/conf/robot_hardware_info.toml`），对应 `nodectl_CD1.yaml`
- 厂商 audio 自 11-26 起**假死**：`/AUDIO/COMMAND` 下发后 card0 全程 closed、`audio_ctl status` 栈溢出崩溃、整机重启无效
- `audio_node.service` 当时 `inactive + disabled`（可能是假死后nodectl未拉起），但 nodectl 配置里 `autostart: true` 埋着复活隐患

### 改动
1. `nodectl_CD1.yaml`：第 64 行 `audio_node.service` 的 `autostart: true` → `false`（只改这一处，其他服务未动）
2. `systemctl stop audio_node.service` + `systemctl disable audio_node.service`

### 终态（改后实测）
- `is-active = inactive`、`is-enabled = disabled`、无 wants 链接、无 audio_node 进程
- `fuser /dev/snd/*` 空 → 无任何进程占用声卡
- `/AUDIO/STATUS` 仍有 1 个 Publisher（`_CREATED_BY_BARE_DDS_APP_`，来自 `deviceCtrl_run.sh` 等裸 DDS 进程），但**不打开声卡、不执行播放**，属无害的发现端点

### 整机重启后复验（13:56，uptime 4 min）
- `systemctl is-active audio_node.service` → **inactive**；`is-enabled` → **disabled**
- `pgrep -af audio_node` → 无进程
- `nodectl_CD1.yaml` 第 64 行仍为 `autostart: false` → **改厂商配置在重启后确实持久生效，无复活隐患**

## 变更二：sayd 改用共享设备（205 / 业务板）

### 改动
`/etc/systemd/system/s10yk-say.service`：
- `Environment=SAYD_ALSA_DEV=plughw:0,0` → `SAYD_ALSA_DEV=default`
- `Description` 同步更新
- `daemon-reload` + `restart s10yk-say`

### 为什么是 `default` 而不是裸 `dmix`
- 裸 `dmix:CARD=rockchipes8388,DEV=0` **不支持 sayd 的 16k/mono**（报 `Channels count non available`）
- `default` 解析到 **pipewire-pulse**（现场 `pipewire`/`pipewire-pulse` 在跑），天然软件混音，16k/mono 实测可用
- 实测双实例：`aplay -D default` ×2 同时 RUNNING，card0 子流由 pipewire 统一持有（aplay 客户端不直接占卡）

### 端到端验证
- 13:43 首次验证：sayd 日志 `dev=default`，TCP 推 PCM 成功（client connected → closed）；**推流期间另一个 aplay 同时运行成功**：`sayd=1 aplay=1`（以前会报 `Device or resource busy`）；结束态 card0 closed
- **13:57 整机重启后复验通过**：sayd `active` + `SAYD_ALSA_DEV=default`，日志显示 `dev=default, idle=1.2s, buf=250ms`；再次 TCP 推 PCM 成功，`sayd=1 aplay=1` 并发运行成功；两个独立 `aplay -D default` 同时 RUNNING（16k/mono），结束态 card0 closed，无残留
- 上述 `Interrupted system call` 是验证脚本 `kill` 正在播放的 aplay 所致，非故障

- **整机重启复验已完成（13:56–13:57）**：`autostart:false` 确实阻止 audio_node 启动，sayd 共享放音正常；原风险项关闭
