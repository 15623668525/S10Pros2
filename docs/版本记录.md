# 版本记录

## v1.0 — 2026-11-14（初版）

**新增**
- 后端 `app.py`（纯标准库 HTTP + rclpy，零 pip 依赖），监听 0.0.0.0:8080
- 运动控制：`/MOTION_STATE`（站立1/软急停2/趴下4）、`/GAIT`（基础0x1001/平地0x3002/楼梯0x3003）、`/api/motion/rl`（RL 控制）
- 速度控制：摇杆 → `/NAV_CMD`，10Hz 下发，600ms 断流自动归零，需 ARM 使能
- 安全：ARM 开关、一键急停（归零+关 ARM+软急停）、速度限幅 0.6/0.4/0.8
- 状态回显：`/MOTION_INFO` 20Hz 订阅（状态/步态/速度/高度/里程）
- 语音播报：`audio_ctl` 封装（预置 9 条 + 自定义 id=200），音色切换、停止
- 自定义语音「小哥哥小姐姐让一下，我在工作啦，请跟我保持3m的距离」（id=200，edge-tts 合成 + ffmpeg 转 16k 单声道）
- 前端单文件页面：虚拟摇杆（触摸/鼠标）、转向轴、状态卡片、语音面板、日志
- systemd 自启单元 `s10yk.service`（Restart=always）
- 落盘约束：`/S10ykRemove` 1GB 配额（ext4 loopback + fstab）

**已知限制**
- 无鉴权（LAN 信任模型）
- 无法远端确认音频是否真正出声（见 D-001）
- `/AUDIO/CONFIG` 音量指令码语义未完全逆向（见 D-004）
- RL 控制下发路径需实机验证（见 D-005）

**新增**

- 素材：`assets/keepdistance.wav`（16 kHz/16 bit/单声道）+ `assets/manifest.json`（中文显示名）。

- 接口实测：`/api/audio/say` → `{"ok":true,"mode":"ssh-aplay","pid":...}`，后端日志 `SAY keepdistance.wav`，无错误回执。
- 预设列表 10 条（9 系统 + 1 自定义）。
- **现场听觉确认（2026-11-14 10:00）：自定义语音「小哥哥小姐姐让一下，我在工作啦，请跟我保持3m的距离」正常播出，音量与系统提示音一致** → v1.2 通路闭环。

## v1.3 — 2026-11-14（站立姿态对齐遥控器）

**修复**
- 「站立」按钮只发 `/MOTION_STATE state=1`，机器狗停在**半蹲**（机身高度 0.2266 m），与厂家遥控器的全站姿不一致。
- 根因（《S10 软件开发指南》2.2.1）：**通过话题下发站立指令后，机器狗不会自动进入 RL 控制态**；只有 ASDU/遥控器接口才会在站立完成后自动进 RL。实测站立(1)=0.2266 m，补发 RL(17)=0.3865 m。
- 修复：`/api/motion/state {state:1}` 改为后端异步序列 —— 发 1 → 轮询 `/MOTION_INFO` 等待高度≥0.20 m 且连续 3 帧稳定（≤2 mm 抖动，最长 8 s）→ 自动补发 17。前端「站立」按钮走该序列并显示"起立中"提示。

**验证（2026-11-14 10:30 实机）**
- 趴下(4) → 高度 0.080 m、state 0；
- 点「站立」：t=1 s state 1 / 0.183 m → t=2 s state 17 / 0.221 m → t=3 s state 17 / **0.385 m**，gait 自动 4097（基础步态），此后稳定 0.386 m。
- 结论：与遥控器站立姿态一致，且进入 RL 后步态已是基础（0x1001），摇杆可直接用。

**变更**
- 后端 v1.3：`stand_sequence()`，`POST /api/motion/state` 的 state=1 走组合序列（返回 `{"ok":true,"seq":"stand(1)->rl(17)"}`）。
- 前端 v1.3：`stand()` + 起立中提示；说明文案改为"站立=起立后自动进 RL 全站姿（≈0.39 m）"。

## v1.4 — 2026-11-14（语音循环播报开关 + 需求文档）

**新增**
- 语音面板新增「🔁 循环播报」开关（`#loopBtn`）：
  - **开**：点击任一语音 → 持续循环，直到点「停止播报」或点击其它语音；
  - **关**（默认）：点击即单次播放。
  - 状态存 `localStorage["s10yk_loop"]`，刷新页面保持。
- 新增《需求文档》（REQ-001 ~ REQ-009 台账 + 详情 + 变更流程），共 5 份文档。

**实现**
- 预置音效：走 `/AUDIO/COMMAND` 的 `repeat` 字段（`0`=无限循环，`1`=单次）；循环时 `preempt=1` 便于新播报抢占。
- 自定义语音：`say_wav(file, loop)` 在内存中把 PCM 数据重复拼接成约 15 分钟的流（`SAY_LOOP_SECONDS=900`，实测 keepdistance.wav 拼 153 次），一次送 SSH 管道给 103 的 `aplay`——播放端零落盘、无重复建链空隙。
- 两路互斥：`/api/audio/play` 与 `/api/audio/say` 入口先 `audio_stop(0)` + `say_stop()`，避免 DDS 循环与 aplay 同时出声。
- 接口：`/api/audio/play {id, loop}`、`/api/audio/say {file, loop}`，响应回带 `loop` / `repeat` 便于前端确认。

**验证（2026-11-14 10:38–10:48，103 声卡 `/proc/asound/card0/pcm0p/sub0/status` 采样）**
| 场景 | 结果 |

| 自定义语音 单次 | t=3s RUNNING → t=9s closed（7.3s 素材播完即停）✅ |
| 自定义语音 循环 | t=3/8/12/16s 持续 RUNNING；点停止后 2s 内 `aplay=0`、pcm closed ✅ |
| 预置音效 单次 id=4 | t=3s 已 closed ✅ |
| 预置音效 循环 id=4 | 12.6s 内持续 RUNNING（单次仅 1.19s）✅ |
| 预置循环 id=3 | 10 秒内 6 段 RUNNING（1.6s 播 + 0.5s 间隔循环）✅ |
| 预置循环 → 自定义 | 切后 aplay 正常占用声卡、无叠加 ✅ |
| 自定义循环 → 预置 | aplay 被终止（1→0），DDS 接管 ✅ |
| 停止播报 | 两路同时归零，无残留进程 ✅ |

**已知特性**

## v2.4 — 2026-11-14（音频通道改造：从"抢占声卡"到"按需占用 + 播完即还"）

**背景**：审计（见《实现方式审计_话题与硬件.md》）指出自定义语音是唯一真正抢占硬件的项——`ssh + aplay` 独占 103 的 `plughw:0,0`，一旦进程残留就把声卡占死，厂商提示音直接丢音。目标是把该项"改成话题"。

**结论：不能 100% 话题化（接口能力限制，非实现选择）**
1. `/AUDIO/COMMAND` 报文只有 `op/id/interval/repeat/priority/preempt`，`op` 仅 `0=PLAY(按 id)`、`1=STOP`，**没有携带文件或 PCM 的通道**。
2. `audio.yaml` 在节点启动时一次性读入，无热加载；新增 id=200 实测无声，需重启节点（节点在第三个隔离容器内，外部不可重启）。
3. 该容器的 `audio.yaml` 与 wav 是私有副本——挪走 106 上同名 wav 后播 id=4 仍完整出声，外部改动无效。

**因此改为"零残留 + 可让路"的实现**（`/api/audio/play`、`/api/audio/say` 接口与返回结构不变，前端无需改动）
- 103 侧新增常驻播放器 `sayd.py`（systemd `s10yk-say`，`Restart=always`），TCP 18081；帧协议 `struct.pack(">BI", type, len)`：`F_START(JSON rate/channels)` → 回 `OK`，`F_PCM`（3200 B/片），`F_STOP`。
- 设备生命周期改为"`START` 才 open，`STOP`/断链立即 close"，空闲 1.2 s 自动释放；单实例互斥。
- 后端 `say_wav()` 改为 TCP 推流，**按 `byte_rate` 实时节流**（每片 100 ms，`SO_SNDBUF=8192`），停止指令 ≤100 ms 生效；循环由本端驱动，避免把整段音频瞬间灌满内核缓冲导致控制连接提前关闭。
- `say_stop()` 双保险：控制连接在就发 `F_STOP`；已被推流线程断开时补发"孤儿 STOP"（另开连接只发一帧）。
- 预置音效改走 `play_preset()`：先 STOP 清场 → 以 `preempt=2(FORCE)` 下发 → 500 ms 内无任何 `/AUDIO/STATUS` 翻转则视为调度器卡死，STOP 后重试一次。

**关键实测（v2.4 依据）**
