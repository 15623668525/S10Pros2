# 三咪头收益最大化方案（拾音距离 / 降噪）（2026-11-26）

## 结论速览

**推荐组合：L1（换 ch1）+ L2（三路选最大）+ L3（单路软件降噪）**，不改硬件、不改 USB 固件，收益约 **+6~12 dB**，等效拾音距离 **×2~4**。**L4 波束成形当前不可行**，须先做远场复测并标定固件延迟。

| 级别 | 措施 | 预期收益 | 改动量 | 风险 |
|---|---|---|---|---|
| L1 | 主用 ch1（FR）替代 ch0（FL） | **+5.7 dB**，距离 ×1.9 | 1 处采集参数 + 帧解析 | 极低 |
| L2 | 三路按帧选能量最大（selection combining） | 方位自适应，稳定拿最强路 | 中（后端帧处理） | 低 |
| L3 | 单路软件降噪（speex NS / WebRTC NS） | SNR +6~10 dB | 中（采集链或前端） | 中（延迟/音质） |
| L4 | 波束成形（延迟求和） | 理论 +4~8 dB | 大 | **当前不可行**，见判定 |

## 实测依据（14:11，业务板）

扫频 chirp 500 Hz→8 kHz，3 s，从机身扬声器 `aplay -D default` 播放，同时 `arecord -c 6` 录制 4 s，FFT 互相关求时延。

| 通道 | RMS | 相对 ch0 | Peak | 判定 |
|---|---:|---:|---:|---|
| ch0 (FL) | 2768.1 | 基准（−21.5 dBFS） | 6616 | 有效，当前在用 |
| **ch1 (FR)** | **5301.6** | **+5.7 dB** | 18355（−5 dBFS） | 有效，**最强** |
| ch2/ch3 (FC/LFE) | 3045.6 | +0.8 dB | 12486 | 有效（两路副本） |
| ch4/ch5 (SL/SR) | 2.6 | −60 dB | 7 | 近静音，排除 |

通道间时延与相关（FFT 互相关，±5 ms 搜索）：

| 通道对 | 时延 | 相关系数 | 折算声程差 |
|---|---:|---:|---:|
| ch0 ↔ ch1 | −2.125 ms | 0.421 | 0.73 m |
| ch0 ↔ ch2 | −5.000 ms | 0.094 | 1.72 m |
| ch1 ↔ ch2 | −2.188 ms | 0.140 | 0.75 m |

### 两个关键判定

1. **时延不是纯声学传播**：0.73~1.72 m 的声程差超过机器狗机身尺寸（约 0.5~0.7 m），物理上不可能。说明 USB 麦阵列固件对各通道施加了**不同的处理延迟**（滤波/重采样/通道对齐），测到的 lag 是"声学时延 + 固件延迟"的混合量。
2. **通道间相关性低**（0.09~0.42）：波束成形要求各通道是同一声源的相干副本，通常相关 >0.8。当前远低于阈值。**注意**：本次声源是机身扬声器（近场 + 机身振动传导），低相关部分源于近场效应，不能直接外推到人声远场——但即便远场相关性改善，固件延迟仍需先标定。

## 硬件约束（决定方案边界）

| 约束 | 实测 | 影响 |
|---|---|---|
| Mic 硬件增益 | 6 路全部 `Capture 25 [100%] [50.00dB]` | **已到顶，没有模拟增益余量** |
| 硬件 AGC | `Auto Gain Control` = `off`，且是 **playback** 控件（非 Mic AGC） | 无硬件自动增益，远近场动态范围靠软件 |
| 采样率 | 固定 16 kHz / S16_LE（hw_params 不可调） | 决定 NS/AEC 只能用窄带算法 |
| 可用 PCM 插件 | `speex`（resample/agc/denoise/echo/dereverb）、`speexrate` | 系统自带 speex DSP，无需新增依赖 |
| 采集卡占用 | pipewire 未注册 USB source，只能直开 `plughw:1,0` | 降噪需在采集后软件处理或自建 pipewire 链 |

## 分级方案详情

### L1 — 换用 ch1（必做，零风险）

当前 `_talk_cmd()` 用 `-c 1` 取 ch0/FL。ch1 比 ch0 高 **5.7 dB**（幅度 1.92×）。

- 实现：`arecord -c 2`（或 `-c 3`）取前 2/3 路，后端按帧取第 2 路；或用 ALSA `plug` 的 route 插件做通道映射。
- 收益：拾音距离 ×1.9（自由场声压每倍距离 −6 dB，5.7 dB ≈ 1.92 倍）。
- 注意：ch1 峰值 −5 dBFS，近场大声可能削波；远场人声幅度小，无此问题。

### L2 — 三路选最大（推荐与 L1 一起做）

声源方位未知时，逐帧（40 ms）计算 ch0/ch1/ch2 的短时能量，选最大的一路送下行。

- 收益：始终拿到当前最强拾音点，避免固定 ch1 在背向说话时反而更差；对移动声源尤其有效。
- 实现：采集改 `-c 3`，后端帧解析从 1280 B（1ch×40 ms）改为 3840 B，按 2 B 步长分三路算 RMS，选路后送回 1280 B。
- 代价：`TALK_FRAME`、队列、前端解析需同步改（见 `技术方案.md` L373）。
- 抗误选：加滞回（连续 3 帧另一路高 3 dB 才切换），避免通道间跳变产生咔哒声。

### L3 — 单路软件降噪

系统已有 `speex` ALSA 插件（`arecord -L` 可见），支持 denoise / agc / dereverb，且 16 kHz 正好匹配。

- 路径 A（后端）：采集时插入 speex 预处理，再走现有 SSH 管道。
- 路径 B（前端）：浏览器 `getUserMedia` 已开 `noiseSuppression: true`，但那是**手机侧**降噪，管不到狗端麦克风。狗端 NS 必须在后端/业务板做。
- 收益：speex NS 典型 SNR +6~10 dB（稳态噪声场景），等效距离再 ×2~3。
- 风险：引入 10~30 ms 算法延迟；强混响或风噪下可能有人声失真，需现场听感确认。
- 建议参数：`denoise=1 agc=0 dereverb=0`（硬件增益已到顶，AGC 关避免二次放大噪声）。

### L4 — 波束成形（暂不可行，附复测方法）

**为什么不行**：通道相关 0.09~0.42，远低于相干要求；且固件延迟未知，TDOA 不可直接用。

**复测判据**（需要人在狗旁 3~5 m 处说话，用外部声源而非机身扬声器）：
1. 录 6ch，计算 ch0/ch1/ch2 两两归一化互相关。
2. 若远场相关 **>0.8** → 有相干基础，可做延迟求和；若仍 **<0.5** → 彻底放弃波束成形。
3. 若相关够，用已知方位声源标定固件固定延迟（同一声源在 0°/90°/180° 各录一次，解出通道间固定偏移），再从测得的 lag 中扣除。
4. 三路阵列孔径小（亚米级），16 kHz 下波束指向分辨率有限，预期增益不会超过 +4~6 dB。

## 拾音距离估算（理想自由场，供设定预期）

声压随距离 `SPL ∝ 1/r`，每倍距离 −6.02 dB；SNR 提升 ΔdB 对应有效距离 `×10^(Δ/20)`。

| 方案 | ΔSNR | 等效距离倍数 | 说明 |
|---|---:|---:|---|
| 基准（ch0，无降噪） | 0 | ×1.0 | 现状 |
| L1 换 ch1 | +5.7 dB | ×1.9 | 实测确定 |
| L1 + L3（NS +8 dB 典型） | +13.7 dB | ×4.8 | 理想值，实际受噪声底/混响限制 |
| L1 + L2 + L3 | +14~20 dB | ×5~10 | 视方位与噪声而定，需实测 |

**重要**：上表是理想自由场上限，室内混响、电机噪声、风噪会显著压缩收益。真实指标须现场用固定声源（如手机在 1/2/3/5 m 播放固定音量语音）逐点测字识别率或 SNR 后给出。

## 落地顺序建议

1. **先做 L1**：改动最小、收益确定，立即验证听感。
2. **再做 L2**：把三路原始流送到后端，选路逻辑可独立开关、A/B 对比。
3. **L3 最后**：先离线录一段噪声场景，用 speex 处理前后对比，确认无人声失真再上线。
4. **L4 单独立项**：先做远场复测，判定通过再投入。

## 备注

- 所有改动都不涉及厂商音频栈（已停用），不引入声卡抢占；采集仍为 `plughw:1,0` 独占单会话。
- 若后续启用双向对讲同时喊话，注意 ch1 近场峰值 −5 dBFS，外放大音量时手机侧 AEC 可能不够，建议戴耳机或降 playback 音量。
- 本方案未执行任何线上改动，仅调研。
