## 4. 故障一：重定位异常 —— 复现成功，且挖出三层根因

### 4.1 现象

- 丢失后自动恢复链路**完全不工作**：监听窗口内「触发自动重定位/开始执行重定位」出现 **0 次**。
- `bbs_reloc` 节点本身健康（BBS 地图 74 万点加载成功），但**从开机起一直"等待 service 触发"，无人调用**。
- 手柄遥测 `Relocation=1, Confidence≈0.4` 全程低位。

### 4.2 根因第一层：自动重定位被门控跳过

```
[08:07:57] 触发无初值自动重定位，但被跳过："当前运动状态不是RL控制(state=-1)"
[08:08:07] 本轮丢失重定位已耗尽，等待人工 /initialpose 或定位自然恢复
```

丢失后唯一自动手段只尝试一次即耗尽，且入口条件是"RL 控制状态"——手动遥控/待机状态下永远进不去。**这是机制性缺陷，不是偶发。**

### 4.3 根因第二层：BBS 全图搜索算力不足，600 秒必然超时

APP「重定位」按钮实际调用了 `/BBS_RELOCALIZE`（use_reference=false → 全图盲搜）：

```
09:30:42  收到BBS重定位服务请求: caller_id=0, use_reference=false, auto_apply=true
09:30:42  室内模式，无有效定位，全图范围搜索
09:30:42  BBS搜索开始: src=13333点, 地图=740634点, threshold=11999(90%), 4线程, timeout=600s
09:30:42  平移搜索范围: 205m × 149m，角度 0~360°，初始变换 1440 个
09:30:46  初始得分统计: 673/1440 超阈值
09:40:42  BBS搜索失败: reason=超时, 耗时600.07s
          popped=12928, children_scored=207136, enqueued=105055, max_queue=93567
```

搜索空间 205m×149m×360°，4 线程 10 分钟只处理了 1/8 的候选队列。**在这张 165m 的大地图上，"无参考位姿的全图 BBS"在该硬件上不可能在超时内完成——按钮在数学上就是无效的。**

### 4.4 根因第三层（新发现）：重启后定位解算未激活

重启（09:17:21）后 localization 长时间停留在：

```
上报状态=0(正常), 可用=0, 运行状态=全局    ← 连续 20+ 分钟、4000+ 条无变化
```

矛盾证据：**09:17:54 Recovery 帧监测显示配准 12/12 全部达标**（err=0.058、inlier=0.988、unmappable=0.08，配准质量极佳），但上报 `可用=0`。即：**配准已经匹配上了，激活门控却不放行**。疑似在等待某个外部使能（RL 状态？任务下发？人工指令？）——需厂家解释 `可用` 位的激活条件。

### 4.5 现场救援记录（部分受阻）

| 手段 | 结果 |
|---|---|
| ROS2 发布 `/initialpose(0,0,0)`（狗已遥控回地图原点） | 发布成功，但 localization 未恢复（仍 `可用=0`，未进入激活流程） |
| ROS2 `ros2 service call /BBS_RELOCALIZE drdds/srv/BbsRelocalize`（use_reference=true 参考位姿） | 请求已发出，**但厂商 drdds 服务未收到**（bbs_reloc 日志无"收到请求"，ros2→厂商裸 DDS 的服务桥不通） |
| 结论 | 服务接口存在（`/BBS_RELOCALIZE` + `reference_pose` 字段），但 ROS2 通用工具无法触达厂商私有 DDS 服务；带参考位姿的局部搜索（可秒级完成）无法从外部触发 |

## 5. 故障二：手柄不显示地图 —— 复现成功，定论不变且加固

厂家条件全部满足 + 狗重启 + APP 重载后，**地图仍不显示**（截图：路线列表有 Task1，右侧「暂无地图」）。

重启后全新会话的完整链路（09:17:38~39）：

```
SFTP 下载 occ_grid_id_map.toml 成功 → 解析成功 → loadMapList() 加载完成 → mapID:null
```

- `loadMap()` / `downLoadMap()` **全天 0 次调用**；
- 手柄本地 `Maps/9634882651828bd0/` 仅 320B 的 TOML，**始终没有 pgm/yaml 底图**；
- 点「新增任务」只创建空任务（`PatrolTask(name=Task1, points=[])`），不触发任何地图下载。

**定论：断链点在 APP 内部"TOML 解析完成 → 选中地图 → 下载底图"之间。服务器端（地图文件/active 激活/8080 服务/网络连通）全部正常。这是 APP 2.5.7 的逻辑缺陷，与机器人端无关。**（详细反编译取证见 OPS-81）

## 6. 综合结论

1. **两个故障均 100% 复现**，且在厂家前置条件全部满足、整机重启、APP 重载的"最干净"条件下依旧复现——排除一切环境性因素。
2. **重定位异常是三层机制问题**：①自动重定位被"非 RL 状态"门控且一次耗尽无兜底；②BBS 全图搜索在该地图规模/算力下 600s 必然超时（无参考位姿时按钮无效）；③重启后解算 `可用=0` 未激活、与配准已达标的监测数据矛盾（疑似激活门控 bug）。
3. **手柄无地图是 APP 侧断链**，与机器人端无关；"重启刷新"路径也被证伪。
4. 现场应急通道（ROS2 工具）因厂商私有 DDS 服务桥不通而无法注入参考位姿——**运维侧没有任何不依赖厂家的外部恢复手段**。

1. 定位丢失后自动重定位为何被"非 RL 控制状态"跳过？耗尽后为何无兜底机制？
2. BBS 全图搜索 600s 超时的参数（timeout/线程数/搜索范围）在哪里配置？能否调大或分区搜索？`use_reference=true` 的参考窗口半径是多少？
3. 重启后 `上报状态=0(正常), 可用=0` 长期不变，但 Recovery 帧监测配准 12/12 达标——`可用` 位的激活条件是什么？是否在等待外部使能？
4. `/BBS_RELOCALIZE` 服务能否从外部（ROS2/SDK）触发？ros2 service call 已按 `drdds/srv/BbsRelocalize` 接口发请求但服务端未收到，桥接方式是什么？
5. APP 2.5.7 成功下载并解析 `occ_grid_id_map.toml` 后为何不调用 `loadMap()/downLoadMap()`（全天 0 次、mapID 恒 null）？地图下载的触发条件是什么？与机器人固件 2.5.6 是否兼容？
